## 1. 研究目标与两个创新

### 1.1 主问题

给定普通、固定的离线轨迹，能否比“只看理想子目标价值”的方法更准确地选择当前控制器真正能够利用的子目标，并提高完整任务成功率？

### 1.2 创新 1：执行感知的后续价值子目标选择

不是只比较 `V(z,g)`，而是先模拟低层控制器追求候选 `z` 后的实际可能结果，再评价这些结果对最终目标的价值，并考虑模型不可靠性。[S1，§9]

### 1.3 创新 2：数据锚定的多时间尺度执行预测校准

使用记录动作在离线数据中真实产生的一步转移和多步终点监督执行预测；不能只让模型互相一致。预测可靠性必须进入创新 1 的评分，并实际影响控制。[S1，§10–11]

```text
普通离线轨迹
    ↓
创新2：训练、校准执行预测模型
    ↓
低层控制器在学习模型中追求各候选子目标
    ↓
创新1：按预计可兑现价值和风险选择子目标
    ↓
真实执行一小段 → 重新观察 → 再次规划
```

**两个创新均为待检验的候选贡献。采用多步损失、集成模型或模型预测控制，本身不是新颖性的证明。**

### 1.4 三个必须回答的实验问题

| 问题 | 需要的证据 | 不足以支持的结果 |
|---|---|---|
| Q1：执行兑现差距是否值得研究？ | 理想评分选中的候选，在真实执行中确实不是较好选择 | 仅证明目标距离不为零 |
| Q2：创新 2 是否改善执行估计？ | 未见轨迹及当前控制器测试中的预测误差、排序误差改善 | 仅训练损失下降，或不同模型彼此一致 |
| Q3：创新 1＋2 是否有系统价值？ | 完整任务提升，且超过同预算的简单模型规划 | 只比不看最终目标的弱对照好 |

## 2. 数据集与实验范围

### 2.1 预定顺序

| 阶段 | 数据集 | 角色 |
|---|---|---|
| 首轮接口与机制 | `antmaze-large-stitch-v0` | 检查长程导航中的预测、候选选择与重规划 |
| 首个操作主实验 | `cube-double-play-v0` | 检查未人工分段操作数据上的执行兑现 |
| 操作扩展 | `scene-play-v0` | 检查多对象、多阶段执行 |
| 后续独立协议 | Kitchen Mixed、图像版、自有 Square/Can | 首轮不启动 |

Maze 的 `stitch` 是短轨迹数据；Cube/Scene 的 `play` 是脚本采集的连续操作经验。官方提供状态输入和目标条件基线。[S2]

**数据名称不证明某种机制一定存在。**不预设 Cube 内存在“不同抓法导致不同插入效果”，也不把完成 Maze 当作三维接触控制已经成立。姿态指标只在数据与任务实际支持时启用。

### 2.2 最小路线与全项目结论

先完成 AntMaze 的接口和机制测试，再按预定路线进入 Cube。若 AntMaze 没有执行兑现差距，可记录“该导航设置没有明显空间”，但不据此断言所有操作任务均无空间。允许再进行一次预先登记的 Cube 检验；两者均无空间时停止当前设计，不无限更换任务寻找正结果。

Scene 的启动以 Cube 最小闭环通过为条件。上述跨环境验证首先是**同一算法分别训练**，不是零样本跨环境迁移。

### 2.3 保持官方任务定义

首轮采用状态输入的目标条件设置，不用 `oraclerep`，不混入 `singletask` 变体的成绩。每个环境覆盖全部官方评价任务，不只挑最有利的目标。

使用官方 `make_env_and_datasets` 接口，冻结 OGBench、MuJoCo、Gymnasium、JAX及基线代码版本。环境时限和成功判定读取冻结版本，不沿用旧 HB 实验的 400 步设定。[S3]

目标奖励、训练奖励、终止掩码必须对齐。尤其要区分**轨迹文件在此结束**与**任务完成、不再进行价值备份**；目标条件重标注产生的奖励也不能与环境奖励未经转换直接混算。[S3][S9]

## 3. 先冻结的定义：没有这些就不要启动长训练

V2 给出了方法接口，但没有把所有实现与参数唯一指定。以下是本计划要求补全的运行合同，不将其伪装成 V2 已决定的内容。

| 字段 | 必须明确的内容 |
|---|---|
| `state_schema` | 控制器与动力学模型能看到哪些状态；是否需要历史；单位和归一化方式 |
| `goal_schema` | 最终目标 `g` 与子目标 `z` 的表示；如何调用低层控制器 |
| `reward_spec` | 奖励值、折扣、目标判定、吸收状态、截断的处理 |
| `tail_value_semantics` | `V` 对应的价值定义；是否只是冻结的保守排序 critic |
| `controller_spec` | 低层算法、时间条件、动作采样、记忆更新、权重哈希 |
| `candidate_spec` | 候选生成器、训练方式、输出约束与候选数量 |
| `prediction_spec` | 一步模型、集成大小、多步损失、概率输出形式 |
| `risk_spec` | 不确定性与离线支持惩罚的具体计算、尺度和系数 |
| `execution_spec` | 规划尺度 `k`、重规划间隔 `m`、剩余预算及早终止处理 |
| `compute_cap` | 训练更新/计算预算、每次决策允许的模型转移次数 |

### 3.1 特别重要：状态输入不自动等于完整动力学状态

某些公开观察未包含全部速度、内部控制器状态或隐藏任务变量。必须审查模型是否具有近似 Markov 输入；缺少信息时，采用有限观察历史等明确方案。不能为了模型预测方便把仅仿真器可读的隐藏信息添加给新方法，却不给基线，也不能声称它属于原观察协议。

### 3.2 子目标与控制器必须真正兼容

首轮建议使用可解码的观察/状态子目标。若复用 HIQL 的潜在子目标接口，必须明确 `z` 的潜在表示、状态到表示映射以及如何评价 `V(z,g)`；不得把潜在向量当成真实物理状态输入动力学。

控制器若不以剩余时间为条件，不可声称其具有精确的“k 步预算条件化能力”。可以实现并离线训练时间条件版本，或将该版本明确标为不使用时间输入的控制器；同一机制对照必须共享完全相同的控制器。

### 3.3 尾值是预测，不是成功概率真值

允许复用目标条件离线 RL 的 `V`，但必须记录其奖励与策略语义。不能把 IQL/HIQL 的价值直接叫作“当前规划系统真实成功概率”。若它只是排序 critic，则报告应写“以冻结尾值为代理的预计收益”，最终仍依赖完整环境结果确认。

## 4. 数据角色与纯离线边界

### 4.1 离线数据划分

保留官方训练集；官方验证集按完整 episode 确定性划分为三个子集。本计划建议比例：

| 子集 | 比例 | 允许用途 |
|---|---:|---|
| `offline_select` | 40% | 预登记范围内选择实现/模型检查点 |
| `offline_calibration` | 30% | 拟合预测区间和风险量的尺度 |
| `offline_audit` | 30% | 冻结后报告多时域预测结果，不继续调参 |

若实际 episode 数不足，先报告样本量并在运行前修改比例。所有窗口从划分后的 episode 中采样；绝不先切窗口再随机拆分。

归一化只用训练集；各方法使用相同原始数据与有效窗口清单。不能为多步模型过滤失败轨迹，而让一步模型使用另一份数据。

### 4.2 环境数据分区

| 分区 | 用途 | 能否回流训练 |
|---|---|---|
| `engineering_pilot` | 重置、保存恢复、时钟、动作语义与数值检查 | 否 |
| `mechanism_gate` | 检查候选兑现差距和方法可行性 | 否 |
| `confirmation` | 冻结后的独立确认 | 否 |

使用环境结果反复选择模型、系数、候选数，同样属于环境反馈，不能用“没有梯度更新”来掩盖。本计划允许前期机制实验决定**是否继续研究**；若据其结果修改算法，必须标明环境指导的开发过程，并使用新的确认集合。

严格版本的权重、归一化、风险标定和候选规则只由离线数据确定。阶段门槛不能被反复查看后调整。

### 4.3 三类结果分开保存

- `DATA_REAL`：记录动作在历史环境中产生的状态，用于训练和离线验证。
- `MODEL_SIMULATED`：当前控制器在学习动力学中的预测，供规划评分。
- `ENV_EVALUATED`：冻结控制器在当前环境测试中的结果，只用于诊断和评价。

模型生成数据不得冒充新增真实轨迹。当前策略的环境测试结果不得追加到动力学或低层训练集。[S1，§6、§12]

## 5. 第一版模型与训练顺序

### 5.1 可替换的基础模块

先训练或严格复现目标条件价值、低层控制器和候选先验，再冻结。GCIQL/HIQL可作为主干参考，但必须遵守上一节的接口约束。

候选先验 `p(z|s,k)` 从训练窗口终点学习；其作用只是提出数据附近的候选，不是证明可达性。第一版只冻结一种生成方式，不同时扫描多种生成架构。具体网络属于 B 阶段实施配置，需要写入清单；不得由环境测试结果挑选候选库。

### 5.2 两个执行预测版本

| 模型 | 训练监督 | 用途 |
|---|---|---|
| `P_1` | 真实一步转移 | 普通模型参照 |
| `P_MH` | 相同步转移＋记录动作的多个时域终点 | 创新 2 主版本 |

两者使用相同网络、集成数量、初始化配对规则、原始数据与优化器。

多步训练中：从真实起点开始，模型中间状态自由滚动，但动作使用数据中记录的动作。不能每一步把真实下一状态重新喂回去，却把它报告为自由滚动多步预测。

### 5.3 推荐的分阶段参数（本计划新增）

| 项目 | 建议值或规则 |
|---|---|
| 原始数据规模 | 标准公开数据，不启动 100M/1B 扩容 |
| 首轮训练种子 | 先 `0` 做机制筛查，通过后补 `1,2`；不能挑最优 seed 汇报 |
| 最终确认训练种子 | `0,1,2,3,4`，在独立确认前完成并冻结 |
| 目标条件主干训练 | 优先复用冻结官方任务配置；首轮上限 1,000,000 updates |
| 动力学集成 | 3 个独立初始化成员；不是 3 个独立评价场景 |
| 动力学更新预算 | 每个版本、每个成员最多 50,000 updates，batch 256，学习率建议 `3e-4` |
| 多步监督时域 | `H={5,10,20,40}`，另保留一步监督 |
| 首轮规划尺度 | `k=20` |
| 首轮执行/重规划间隔 | `m=5` |
| 每次候选数 | `N=8` |
| 初始候选模拟 | 每候选、每集成成员 1 次；随机环境另冻结粒子数 |
| 正式超参数网格 | 首轮不启用；缺失参数先用离线预检固定 |

官方 OGBench 主训练入口默认给出 1,000,000 步训练，但这不是所有新模块的统一合理预算，也不代表本计划已复现其性能。[S10]

上述值是**有界起点**，不是最优配置或功效保证。在运行前测量显存、每 1,000 次更新耗时和每次决策耗时，形成资源估算；超出预算就暂停，不能静默减少基线训练而保留新方法计算。

### 5.4 多步训练公平性

相同 updates 不等于相同计算量：多步反向传播通常计算更多。主报告提供同 updates 对照，并增加 `P_1_compute_matched`：按预先测得的总计算上限给一步模型更多训练或容量预算，检查是否只是训练算力更多。需要记录模型步数、训练曝光、wall time 和显存。

## 6. 执行预测与候选评分：冻结的数学含义

### 6.1 离线模型监督

从同一 episode 抽取窗口：

\[
(s_t,a_t,\ldots,a_{t+h-1},s_{t+h}^{\mathcal D}).
\]

模型使用记录动作递归预测，得到 `s_hat[t+h]`，再与真实数据终点比较：

\[
\mathcal L_{\mathrm{model}}
=\mathcal L_{\mathrm{1step}}
+\lambda_m\sum_{h\in\mathcal H}\alpha_h
\ell_h\bigl(\chi(\hat s_{t+h}),\chi(s_{t+h}^{\mathcal D})\bigr).
\]

首轮不强制增加直接宏观模型；因此 `L_scale=0`。只有独立宏观预测器与递归模型确实描述同一动作序列时，才在后续扩展中增加跨尺度协调，并同时监督二者接近真实终点。[S1，§10.3–10.4]

### 6.2 测试时模拟的是当前控制器的动作

对候选 `z`，复制当前状态与控制器上下文：

\[
\tilde a_i\sim\pi_\theta(\cdot\mid\tilde s_i,z,k-i),\qquad
\tilde s_{i+1}\sim\widehat P_\eta(\cdot\mid\tilde s_i,\tilde a_i).
\]

每个模型分支分别依据其预测状态查询控制器；不能把真实环境中的未来动作提前提供给规划器。主模拟长度为 `m`，因为部署后也在 `m` 步重新规划。

### 6.3 评分

\[
\widehat J_m(s,z,g;k)
=\mathbb E\left[\sum_{i=0}^{m-1}\gamma^i r_i(g)
+\gamma^m\bar V(\tilde s_m,g)\right],
\]

\[
S_m=\widehat J_m-\lambda_U U-\lambda_{\mathrm{ood}}O.
\]

成功、真正终止和剩余任务时限的掩码需要进入公式实现；任务已完成后不能再奖励尾值。风险量的单位要与价值相容，标定仅使用离线校准集。

首轮的 `U` 可采用集成评分分歧；`O` 采用一种预登记的状态—动作支持度度量。二者是保守启发式，不是自动成立的置信下界。只有经过留出数据的覆盖率/误差关联检查后，才能使用“校准”一词描述相应量。

### 6.4 不能把“执行 m 步”理解成“必须在 m 步到达 z”

`z` 是规划尺度 `k` 下的子目标，而 `m<k` 是下一次重新规划前的执行长度。因此，5 步后未达到 20 步子目标不自动构成控制失败。主评分看这 5 步带来的收益和后续价值；完整 `k` 步的到达误差只作为另一个诊断量。

## 7. 实验矩阵：分别隔离两个创新

### 7.1 机制主矩阵

所有以下方法共享相同 `V`、`pi`、候选生成器、候选数、规划尺度和执行间隔。

| ID | 选择规则/模型 | 回答的问题 |
|---|---|---|
| `IDEAL` | 用 `V(z,g)` 排序 | 不建模执行时怎样 |
| `EXEC_1` | 用 `P_1` 模拟控制器，按 `S_m` 排序 | 创新 1 相对理想评分是否有用 |
| `EXEC_MH` | 换成 `P_MH`，其他相同 | 创新 2 是否提供额外收益 |
| `EXEC_MH_NO_RISK` | 保留执行评分，不扣除 `U/O` | 风险项是否必要 |
| `MPC_EQ` | 用相同动力学、奖励、尾值优化原始动作序列 | 是否仅增加模型规划就足够 |
| `ORACLE_DIAG` | 诊断环境分叉结果作事后候选比较 | 只看机会空间，不参与主方法排名 |

`EXEC_MH` 是首轮预设主方法。主比较为 `EXEC_MH−EXEC_1`；创新 1 的预设比较为 `EXEC_1−IDEAL`。只有与强外部基线和 `MPC_EQ` 的比较也成立，才讨论完整方法价值。

### 7.2 强外部基线

首轮加入官方 GCIQL、HIQL；操作确认阶段加入 SHARSA。GCBC用于下界与接口 sanity check，不是唯一对照。[S2][S4]

FQL在 V2 中列为基线。若采用 `horizon-reduction` 仓库中的目标条件实现，可以在对齐数据、观察和奖励后加入；不能直接用单任务 FQL 成绩冒充多目标比较。该仓库确实提供目标条件 FQL 与 SHARSA，但其部分公开配置使用大数据和 `oraclerep`，不直接照搬成绩。[S4][S5]

本计划不一开始增加全部序列生成、轨迹增广算法；机制通过后，再针对最接近的方法确定投稿级比较矩阵。

### 7.3 计算预算公平性

对模型候选选择器，每次重规划的基本模型转移调用数为：

\[
B=N\times M\times P\times m.
\]

初值 `N=8,M=3,P=1,m=5` 对应 `B=120` 次单样本模型转移，实际批处理耗时另报。

`MPC_EQ` 必须使用同一 `B` 及同一尾值/支持惩罚，并事先冻结搜索算法、迭代数和总候选数。不能给新方法大量候选，却给 MPC 极少搜索。需要额外报告低层网络调用、规划延迟、峰值内存；有相同模型调用数也不等于总推理计算完全相同。

`IDEAL` 本来就更便宜，不必人为让其空转；报告自然成本，并提供各方法的性能—计算曲线。增加预算的点必须在看到测试成绩前登记。

## 8. 阶段 A：环境、数据与版本预检

**目标：先确认实验能够合法且可重复地运行。**

操作：

1. 新建独立代码目录与运行根目录；旧项目与旧结果只读。
2. 冻结代码、依赖及数据文件哈希，记录公开数据版本和许可。
3. 从官方接口加载第一个环境与 train/val，统计 episode 数、转移数、长度分布与合法多步窗口数。
4. 检查观察/动作形状、动作边界、单位、四元数顺序、任务标志和奖励语义。
5. 实现 episode 级数据划分与训练集归一化，验证窗口不跨 reset。
6. 在最多 8 个工程 reset 上检查确定性、状态保存恢复、控制器上下文和终止计数。
7. 在普通部署模式禁止访问候选的环境未来结果，检查日志与 planner 的信息隔离。

交付：`environment_manifest.json`、`dataset_manifest.json`、`split_manifest.json`、`interface_audit.json`、`resource_estimate.json`。

停止条件：数据/动作语义不清、无法可靠保存恢复、状态模型输入严重缺失、需要泄漏隐藏状态才能运行。此时状态为 `HOLD_INTERFACE_OR_DATA`，不是研究假设失败。

## 9. 阶段 B：基础模块离线训练与冻结

**目标：建立一个不是人为削弱的、可审查的控制器和统一候选来源。**

按 V2 的分阶段原则训练 `V`、低层控制器、候选先验；全部训练来源为离线数据。记录是否使用官方实现、修改文件与参数差异。预登记中间检查点，选点仅使用离线验证规则，或统一使用固定最终检查点。

检查：

- 同一候选输入是否得到合法动作；时间预算是否按实际执行递减。
- `V` 的奖励标度是否与规划累积奖励一致。
- `p(z|s,k)` 是否产生明显无效状态，是否退化为重复同一候选。
- `z=s`、相邻历史终点等简单输入是否能通过接口测试，但不把它们的成绩当创新证据。
- 不通过额外噪声、减少训练或人为错误控制器制造兑现差距。

若使用公开 checkpoint，必须确认同数据版本、同输入和同奖励；若没有合适 checkpoint，就显式计入新训练成本，不假设资源已经存在。

交付：`backbone_manifest.json`、三类模型哈希、`candidate_audit.json`、`reward_value_contract.json`。

**阶段 B 结束后才进入研究方案中的“阶段 0”机制检查。**“不实现完整系统”不等于可以跳过基础控制器准备。

## 10. 阶段 0：执行兑现差距的有界诊断

**目标：在不训练复杂执行模型前，检查是否存在值得纠正的候选选择空间。**[S1，§22]

### 10.1 建议规模

每环境先用 1 个训练种子、32 个独立 reset root，覆盖全部官方目标。每 root 最多一个预登记决策点；位置可从 `0、1/4、1/2` 官方时限中按固定哈希分配，使用冻结参考策略执行前缀得到现场快照。

在到达决策点前已经结束的 root 如实记录，无合法候选诊断，不因其不利于假设而替换。有效 root 少于 24 时标记样本不足；任何补充规则必须在看候选结果前设定。

每个合法决策点固定同一组 `N=8` 候选。对每候选最多 2 个预登记执行随机带；确定性模式下相同重跑只用于复现性检查，不能算额外独立样本。

### 10.2 获取候选环境结果

恢复同一环境快照，对每个候选使用同一个冻结控制器，按统一协议执行，记录 `m`、`k` 及最长 40 步的结果。候选分叉是评估手段，不是方法所需的训练 pair。

环境快照必须包括物理状态、随机状态、任务状态、wrapper时钟和策略上下文。只保存 observation 后重新赋值不一定是有效恢复。

### 10.3 两种量必须分开

V2 的：

\[
J^{\mathrm{proxy}}_{\mathrm{env},m}
=\sum_{i<m}\gamma^i r_i^{\mathrm{env}}
+\gamma^m\bar V(s_m^{\mathrm{env}},g)
\]

是**真实短程执行＋学习尾值的代理量**，不是完整环境真回报。另记录执行满 `k` 步的同类代理，避免把 k 步理想终点与 m 步中间状态机械相减而制造差距。

对预先选定的 8 个 root，再在每个候选执行 `m` 步后，统一使用同一冻结后续策略直到官方时限，得到完整环境回报 `G_env` 与任务成功。这个深度诊断不使用新方法选择性挑选的 root。

`G_env` 仍对应规定的后续策略，不是“从这个状态最优能做到什么”。实际完整规划系统的表现将在阶段 E 单独评价。

### 10.4 指标与判定

报告候选内排序相关、top-1并列处理、事后最佳候选的经验 regret，以及 `V(z,g)` 高但执行收益低的比例。每个 root 先汇总，候选不能当独立样本；大量回报同为零时报告不可区分比例，不能用微小噪声创造排序。

本计划建议的探索门槛：至少 24 个合法 root；至少 10% 合法 root 出现超过预登记价值容忍度的错选。容忍度可设为离线 `V` 标准差的 5%，尺度只用离线数据确定。

以上只说明有机制空间，不是方法通过。若只有代理量有差异、完整环境结果没有可分辨证据，标记 `GAP_PROXY_ONLY`；若两种量均无可利用差异，标记 `NO_USEFUL_GAP_ON_THIS_TASK`。

允许进入下一步的状态：`GAP_PRESENT_PROVISIONAL`。不允许把事后候选最优者当作可部署算法或安全上界。

## 11. 阶段 C：一步模型下验证创新 1

训练 `P_1`，不加多时域终点损失。所有模型权重与评分参数使用离线数据确定并冻结。

对固定候选集，比较 `EXEC_1` 与 `IDEAL`。候选必须先保存再评分；禁止 `EXEC_1` 多采候选或使用额外成功筛选。

同时比较预测的 `J_hat_m` 与环境代理 `J_env,m`，拆出：

- 终点状态预测误差；
- 相同尾值下的价值误差；
- 不确定性是否识别大误差；
- 最终选中候选的排序收益。

对先前已看过的阶段 0 root 可以做事后诊断，但结论标为开发证据。继续决策应使用事先冻结的新机制 root 清单，不能把阶段 0 当成独立确认。

进入下一步：执行评分相对 `IDEAL` 至少有正向候选排序/收益信号，且未出现无法识别的模型利用。如果一步模型明显失效但阶段 0 显示机会空间，则保留一次阶段 D 的多时域检验；不得无限更换模型。

交付：`one_step_audit.json`、`candidate_scores.jsonl`、`execution_error_by_horizon.csv`、`innovation1_gate.json`。

## 12. 阶段 D：多时域数据校准验证创新 2

固定阶段 B 的所有模块，只训练 `P_MH`。主方法与 `EXEC_1` 只改变执行模型训练，风险标定采用相同规则；不重训更强低层控制器来冒充创新 2 的贡献。

### 12.1 离线审计

建议在 `offline_audit` 中固定最多 256 个不同 episode，每个 episode 抽取相同起点覆盖 `H` 的合法窗口。若不足则全部使用，记录真实数量；按 episode 聚类。

报告一步、5/10/20/40 步自由滚动误差。`m=5` 对齐部署评分，应作为主预测时域；仅改善 40 步而不影响 5 步评分，不足以支持当前部署设置的创新 2。

### 12.2 当前控制器测试

冻结后分别让当前低层控制器在模型和诊断环境中追求相同候选。明确区分：

1. 记录动作下的模型误差；
2. 当前策略在模拟状态上自行生成动作时的闭环误差。

第一项改善不自动意味着第二项改善。第二项的环境数据只用于测试，不用于补训。

### 12.3 校准链条

必须检查：

\[
\text{多时域训练}
\rightarrow\text{执行估计改善}
\rightarrow\text{候选排序改善}
\rightarrow\text{完整任务改善}.
\]

先补齐三个训练种子并报告每个种子结果，不挑表现最好的那一个。探索门槛建议：主时域预测误差点估计不变差，候选收益相对 `EXEC_1` 的种子均值为正，且至少 2/3 种子方向为正。该门槛不是正式显著性证明。

如果离线预测更准但真实当前策略预测未改善，状态为 `OFFLINE_FIT_ONLY`；如果预测更准而选择不变，为 `PREDICTION_GAIN_WITHOUT_DECISION_GAIN`。均不自动进入正式全系统确认。

交付：`model_comparison.json`、`calibration_report.md`、`innovation2_gate.json`。

## 13. 阶段 E：完整长任务的最小系统检验

### 13.1 执行伪代码

以下是需实现的行为合同，不是已存在的训练/运行命令。

```text
冻结 V、低层策略、候选生成器、执行模型、风险尺度与评分参数
从官方任务初始分布 reset
while 尚未成功且未超时:
    根据当前真实观察生成固定数量候选
    对每个候选:
        复制当前控制上下文
        用学习模型 + 当前低层策略模拟 m 步
        按沿途奖励、尾值、模型分歧、离线支持度计算分数
    选择最高分候选
    在环境里闭环执行最多 m 步，每一步重新读取真实观察
    如果任务提前终止，则立即停止
    否则重新生成候选并规划
保存完整结果；不更新任何网络、normalizer或风险参数
```

评分过程中不能通过真实仿真器试候选。`ORACLE_DIAG` 必须使用单独进程/入口，避免其快照、未来回报或动作进入主 planner。

### 13.2 建议规模

每环境先覆盖全部 5 个任务，每任务 8 个新 reset root，共 40 个 root；三个训练种子；至多 8 个方法版本。

```text
最多记录数 = 40 roots × 3 training seeds × 8 methods = 960
```

这是 40 个环境 root 上的相关配对记录，不能说有 960 个独立测试场景。相同任务、root、训练种子的各方法共享环境初始条件和预登记随机带。模型模拟随机数与真实环境随机数分开。

### 13.3 核心结果

报告完整成功率、任务回报、完成步数、规划耗时与失败案例；以环境正常起点执行，不只从方便的中间状态测试。

系统 GO 的建议标准：`EXEC_MH` 相对 `EXEC_1` 有正向净收益，至少 2/3 种子方向为正；相对 `IDEAL` 和 `MPC_EQ` 不出现明显退化；预测—排序—任务结果具有一致改善证据。若只改善模型损失或只在明显弱基线上获胜，不进入投稿级确认。

开发规模较小时区间可能很宽。标记为方向性证据即可，不通过追加 root 把区间“跑到显著”。

## 14. 阶段 F：独立确认与操作扩展

阶段 E 通过、具体方法和资源预算获确认后才启动。本计划不默认一次性运行全部大矩阵。

### 14.1 首个确认环境与比较

优先确认 `cube-double-play-v0`；AntMaze 作为机制结果保留。之后按同一方法和参数选择规则进入 Scene，不能根据 Scene 测试成绩重新选模型。

建议确认矩阵：

1. `IDEAL`
2. `EXEC_1`
3. `EXEC_MH`
4. `MPC_EQ`
5. GCIQL
6. HIQL
7. SHARSA

必要消融 `EXEC_MH_NO_RISK`、`P_1_compute_matched` 等另列诊断，不为了压缩表格隐去关键反证。

### 14.2 建议预算与功效检查

建议每个确认环境 5 个训练种子、每官方任务 40 个新 root，合计 200 个 root。七种方法对应：

\[
7\times5\times200=7000
\]

条完整结果记录/环境。实际环境步数上限为 `7000 × official_episode_limit`，还需计入机制分叉与模型模拟计算。

**这只是资源建议，不是功效保证。**在查看确认集之前，使用开发期根级配对方差和训练种子差异做规划；建议最小有意义成功率提升先设为 5 个百分点。若预算不足以辨别这一量级，明确定位为有限规模确认，不承诺“必然通过”。样本量和分析规则必须在生成确认结果前最终冻结。

### 14.3 声明边界

同环境新 reset 只能支持同任务分布下的独立确认。跨任务组合未见性、零样本跨环境、姿态精度改善和图像部署，均需要专门的协议和数据审计，不能由总体成功率推导。

## 15. 指标与统计

### 15.1 主要与次要指标

| 层面 | 主指标 | 次要指标 |
|---|---|---|
| 执行预测 | 部署时域 m 的任务归一化预测误差 | 全时域误差曲线、NLL、覆盖率 |
| 候选决策 | 相同候选集上的平均经验选择 regret/收益差 | 排序相关、top-1 并列命中、错误选择比例 |
| 完整控制 | 官方任务成功率 | 回报、完成步数、失败原因 |
| 计算 | 每次决策 wall time 与模型调用数 | 训练时间、显存、粒子数、候选数 |

不能把归一化位置误差降低直接等同于任务成功提高。

### 15.2 三维状态的处理

按 V2 使用任务相关位置、旋转、夹持/接触与离散任务状态。米和弧度不能直接相加；旋转使用合法的 SO(3) 距离，四元数符号等价和物体对称性需处理。[S1，§7]

若官方任务不考察某种姿态，不能私自加入姿态门槛改写成功率。若输入无法提供所需姿态，则该指标为不适用；隐藏真值可用于单独的评估审计，但不得成为主方法独有输入。

### 15.3 独立单位与不确定性

- 离线预测：按原始 episode 聚类；重叠窗口不独立。
- 候选诊断：按 root 聚类；同 root 的候选、模拟粒子不独立。
- 系统结果：先在 task 内计算方法间 root 配对差，再宏平均任务。
- 训练随机性：报告每个训练 seed、种子均值和最差值；共享 root 的多个 seed 不是新增环境样本。

建议同时给出条件于冻结模型的 root-bootstrap 区间，以及联合考虑 seed 与 root 的双向重采样敏感性分析。训练 seed 数少时不声称后者有严格有限样本覆盖保证。主分析一次生成并缓存 bootstrap 索引，所有摘要引用同一结果，避免同一估计量在报告不同位置出现不同区间。

首轮建议 5,000 次重采样，固定统计 seed。极端二元数据或全部并列时，补充计数与适当的敏感性分析；不把浮点误差当显著差异。

### 15.4 确认性主张

确认前锁定一个主比较 `EXEC_MH−EXEC_1`，其余机制和外部比较按预登记顺序报告。若同时对多个外部基线宣称优越性，使用预登记的多重比较校正，不能事后挑出某个正区间作为全部方法成立的证据。

只有当“执行估计改善”和“完整控制改善”均有证据时，才支持创新 2 的闭环价值；不能用其中任意一个替代另一个。

## 16. 工程测试清单

以下是**待实现并执行**的测试要求，不是已通过的测试数量。

1. 窗口索引不跨 episode；长度不足时不伪造终点或下一状态。
2. 训练、选择、校准、审计的 episode 与来源关系不泄漏。
3. goal relabeling、奖励、discount和终止掩码在价值与规划中一致。
4. `m<k`、剩余时间、任务早终止、达到子目标后的行为均定义清楚。
5. 模型闭环动作来自预测状态；真实环境闭环动作来自真实状态。
6. 多步监督使用记录动作和真实终点；不存在“输入 z、输出复制 z”的伪监督。
7. 集成成员、控制器隐状态和 RNG 在候选之间隔离。
8. 同协议重复执行、保存恢复与规划前后无污染检查。
9. 关闭重规划的消融不偷偷重选候选；跨尺度比较不混入不同控制协议。
10. 主 planner 无环境未来查询；oracle诊断在不同入口隔离。
11. 风险尺度来自离线校准；对无效预测有固定回退规则，不静默调用教师。
12. 每个 episode 唯一键、coverage与失败原因完整；失败记录不得删除后只汇报成功子集。

回退规则需预先固定，可使用同一目标条件主干直接控制；记录回退率。若候选大面积无效，视为模型/候选机制问题，而不是靠回退掩盖。

## 18. Go / No-Go 总表

| 条件 | 结果状态 | 行动 |
|---|---|---|
| 数据、重置或输入语义不满足 | `HOLD_INTERFACE_OR_DATA` | 修复接口，不启动长训练 |
| 控制器/候选明显失效 | `HOLD_BACKBONE_OR_CANDIDATES` | 先复现合格主干，不把弱控制当创新空间 |
| 无明显可纠正的兑现差距 | `NO_USEFUL_GAP_ON_THIS_TASK` | 按预定第二任务核查一次，不无限挑任务 |
| 只有代理收益存在差距 | `GAP_PROXY_ONLY` | 不宣称真实任务空间已成立 |
| 执行评分带来方向性收益 | `EXECUTION_SELECTION_SIGNAL` | 继续校准验证，不称正式成功 |
| 多步仅改善离线拟合 | `OFFLINE_FIT_ONLY` | 不升级完整方法贡献 |
| 预测改善但排序或控制未改善 | `PREDICTION_GAIN_WITHOUT_CONTROL_GAIN` | 限定结论，检查是否存在实际决策作用 |
| 多时域评分改善控制但不胜简单MPC | `MODEL_PLANNING_GAIN_ONLY` | 不宣称独立新机制优势 |
| 机制、控制及公平强对照均支持 | `EXECUTION_ALIGNED_GAIN_SUPPORTED` | 进入预定操作扩展与投稿级确认 |
| 需要追加当前策略交互才能成立 | `REQUIRES_ONLINE_CALIBRATION` | 另立offline-to-online协议，保留原纯离线结果 |

NO-GO 后不追加训练直到通过，不改主比较，不只留下最佳 seed。新的设计使用新版本、新冻结文件和新的独立确认数据。

## 最终摘要

**训练时：**用普通离线轨迹训练价值、低层控制和候选先验；用真实记录动作的一步与多步结果校准执行预测。  
**测试时：**模拟当前控制器追求各候选后会发生什么，按预计可兑现收益与风险选子目标，执行 `m` 步，再重新规划。  
**创新验证：**先确认兑现差距存在，再确认模型更准能改变选择，最后确认选择改善能超过等预算规划与强分层基线。  
**停止原则：**没有机制空间、只有预测损失改善，或只靠更多搜索取胜，都不足以支持完整方法。
